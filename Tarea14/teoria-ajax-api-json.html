1. ¿Qué es AJAX?

AJAX = Asynchronous JavaScript And XML. El nombre es viejo (de cuando XML era el formato común), pero la idea sigue siendo la misma: pedirle datos a un servidor sin recargar la página, usando JavaScript de forma asíncrona.

Hoy casi nadie usa XML para esto — se usa JSON — pero el nombre "AJAX" se quedó para referirse a cualquier petición asíncrona de datos desde el navegador.

2. ¿Qué es una API?

Una API (Application Programming Interface) web es, en este contexto, un servidor que expone URLs donde se le puede pedir (o mandar) información. Cada URL es un endpoint.

Ejemplo real: https://randomuser.me/api/ regresa datos de una persona inventada al azar cada vez que se visita. Hay compendios enormes de APIs públicas y gratuitas para practicar (buscar "public apis github" es un buen punto de partida).

3. JSON

JSON (JavaScript Object Notation) es el formato estándar para representar datos como texto: objetos con { }, arreglos con [ ], llaves siempre entre comillas dobles.

{
  "nombre": "Ana",
  "edad": 23,
  "intereses": ["música", "ciclismo"],
  "direccion": {
    "ciudad": "CDMX",
    "cp": "01000"
  }
}
JSON no es exclusivo de JavaScript — es un formato de texto universal. Cualquier lenguaje puede leerlo o generarlo. En JS, se convierte un string JSON a objeto con JSON.parse(), y un objeto a string JSON con JSON.stringify().

4. Probando APIs sin escribir código EXTRA

Antes de programar nada, conviene explorar la API a mano con una herramienta como Hoppscotch: se pone la URL, se elige el método (GET, POST...) y se ve la respuesta completa, con sus headers y su código de estado — así ya se sabe qué esperar antes de escribir el fetch.

5. Códigos de estado HTTP

Toda respuesta HTTP viene con un número de 3 dígitos que dice qué pasó:

Rango Significa Ejemplo
2xx Éxito 200 OK, 201 Creado
3xx Redirección 301 Movido permanentemente
4xx Error del cliente 404 No encontrado, 400 Petición inválida
5xx Error del servidor 500 Error interno
Esto es clave para fetch: un 404 o un 500 SÍ es una respuesta (el servidor contestó), no un fallo de red. fetch solo rechaza (cae en catch) cuando no pudo ni conectarse (sin internet, dominio no existe, etc.). Para detectar un 404 hay que revisar explícitamente el código de estado (sección 9).

6. Query strings

La parte de una URL después de ? manda parámetros al servidor, como clave=valor separados por &:

https://ejemplo.com/buscar?termino=gatos&pagina=2

Si el valor tiene espacios o caracteres especiales, hay que codificarlo con encodeURIComponent() para que la URL siga siendo válida:

const termino = "pan dulce";
const url = `https://ejemplo.com/buscar?q=${encodeURIComponent(termino)}`;
// -> https://ejemplo.com/buscar?q=pan%20dulce

7. XMLHttpRequest (la forma vieja) EXTRA

Antes de fetch, las peticiones se hacían con XMLHttpRequest. No soporta promesas — todo es con callbacks (onload, onerror):

const req = new XMLHttpRequest();
req.onload = function () {
  const data = JSON.parse(this.responseText);
  console.log(data);
};
req.onerror = function () {
  console.log("Error de red");
};
req.open("GET", "https://ejemplo.com/api");
req.send();

Hoy casi no se usa directamente, pero ayuda a entender por qué fetch (que sí regresa promesas) fue una mejora tan grande.

8. fetch

fetch(url) regresa una promesa que resuelve con un objeto Response — que todavía NO es el JSON, es la respuesta HTTP completa (headers, status, etc). Para obtener los datos hay que llamar a .json() sobre esa respuesta, que a su vez regresa OTRA promesa:

fetch("https://ejemplo.com/api")
  .then((response) => {
    console.log(response.status); // 200, 404, etc.
    return response.json(); // otra promesa
  })
  .then((data) => {
    console.log(data); // ya son los datos como objeto JS
  })
  .catch((error) => {
    console.log("Fallo de red:", error.message);
  });

9. fetch con async/await

El mismo patrón, más legible con await:

async function obtenerDatos() {
  const response = await fetch("https://ejemplo.com/api");
  const data = await response.json();
  console.log(data);
}

10. Los DOS tipos de error al usar fetch

Esta es la parte que más se presta a confusión: fetch distingue entre no poder conectarse y conectarse pero recibir un error.

Caso ¿Qué hace fetch? ¿Cómo se detecta?
Sin internet, dominio no existe, CORS bloqueado La promesa de fetch() RECHAZA try/catch (o .catch())
El servidor respondió con 404, 500, etc. La promesa de fetch() RESUELVE normalmente Revisando response.ok (o response.status) a mano 
async function obtenerDatos() {
  try {
    const response = await fetch("https://ejemplo.com/api/algo-que-no-existe");

    if (!response.ok) {
      // El servidor SÍ contestó, pero con error (p. ej. 404).
      throw new Error(`Error ${response.status} al pedir los datos`);
    }

    const data = await response.json();
    console.log(data);
  } catch (error) {
    // Aquí caen TANTO los errores de red como los que se
    // lanzaron a mano arriba por un response.ok === false.
    console.log("Falló:", error.message);
  }
}
Si solo se usa try/catch sin revisar response.ok, un 404 se trata silenciosamente como si todo hubiera salido bien — response.json() incluso puede funcionar sin lanzar error, con un cuerpo de error del servidor en vez de los datos esperados.

11. Repaso: usar los datos que llegan de la API

Los datos de una API casi nunca vienen listos para mostrarse. Estas son las herramientas de JavaScript que más se usan con ellos.

Promedio con reduce (cuidando el arreglo vacío, para no dividir entre 0): 

function promedio(valores) {
  if (!valores || valores.length === 0) return null;
  const suma = valores.reduce((total, v) => total + v.puntos, 0);
  return suma / valores.length;
}

Redondear decimales con toFixed(n) (regresa texto):

(4.3333333).toFixed(1); // "4.3"

Un texto distinto según el valor, con un ternario, y un valor por defecto con ||:

const resultado = promedio(valores);
const texto = resultado === null ? "Sin datos" : `${resultado.toFixed(1)} puntos`;

const autor = dato.autor || "Anónimo"; // si autor no existe o es null

Una imagen: se crea con createElement y se le asigna src (la URL) y alt (texto alternativo):

const img = document.createElement("img");
img.src = dato.urlImagen;
img.alt = dato.titulo;
tarjeta.append(img);
Para pintar los elementos usa createElement y textContent; evita innerHTML con datos que vienen de fuera. Para vaciar un contenedor basta con contenedor.textContent = "".
