1. Código async

Pedir datos a un servidor, esperar un cobro, o simplemente usar setTimeout, son operaciones asíncronas: no terminan al instante. JS sigue ejecutando el resto del código mientras espera, y avisa cuando termine.

console.log("1. Antes");
setTimeout(() => console.log("2. Se obtuvieron los datos"), 3000);
console.log("3. Después");

// Orden real en consola: 1, 3, 2

El reto es: ¿cómo organizamos código que depende del resultado de algo que todavía no ha terminado?

2. Callbacks (la forma vieja) EXTRA

La primera solución fue pasar una función que se ejecuta cuando el resultado está listo: un callback.

function fakeRequest(url, success, failure) {
  const delay = Math.floor(Math.random() * 3000) + 1000;
  setTimeout(() => {
    if (delay <= 3000) success(`Respuesta de ${url}`);
    else failure("Connection timeout");
  }, delay);
}

fakeRequest("/page1",
  (respuesta) => console.log(respuesta),
  (error) => console.log(error)
);
El problema aparece cuando se necesitan varias peticiones en orden, una dentro de la otra: el código se anida cada vez más ("callback hell") y se vuelve difícil de leer y de manejar errores.

3. Creando una promesa

Una Promise es un objeto que representa un valor que todavía no existe, pero que existirá (o fallará) en el futuro. Se crea con new Promise(), que recibe una función con dos parámetros: resolve (éxito) y reject (error). 

function fakeRequestPromise(url) {
  return new Promise((resolve, reject) => {
    const delay = Math.floor(Math.random() * 3000) + 1000;
    setTimeout(() => {
      if (delay <= 3000) {
        resolve(`Respuesta de ${url}`); // éxito: pasa el valor a resolve
      } else {
        reject(new Error("Connection timeout")); // error: pasa el error a reject
      }
    }, delay);
  });
}

Una promesa siempre está en uno de tres estados: pending (esperando), fulfilled (se resolvió) o rejected (se rechazó). Una vez que resuelve o rechaza, ya no cambia.

3.1. Validar y rechazar

Una promesa también sirve para validar algo: se resuelve si el valor es válido y se rechaza con un Error si no. Para comprobar que un texto tenga exactamente cierta cantidad de dígitos hay dos formas:

// 1) Contar caracteres (pero también acepta letras)
valor.length === 5;

// 2) Expresión regular: exactamente 5 dígitos y nada más
/^\d{5}$/.test(valor);   // true o false

function validarCodigo(valor) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (/^\d{5}$/.test(valor)) {
        resolve();
      } else {
        reject(new Error("Código inválido"));
      }
    }, 500);
  });
}
En la regex, ^ y $ marcan el inicio y el final del texto, \d es "un dígito" y {5} es "exactamente 5 veces". Sin ^ y $, "abc12345xyz" también pasaría.

4. Consumiendo una promesa: .then() y .catch()

.then() recibe el valor cuando la promesa resuelve; .catch() recibe el error cuando rechaza.

fakeRequestPromise("/page1")
  .then((respuesta) => {
    console.log(respuesta);
  })
  .catch((error) => {
    console.log(error.message);
  });
A diferencia de los callbacks, una promesa SIEMPRE tiene un solo lugar para manejar el error (.catch()), sin importar cuántos .then() tenga encadenados.

5. Encadenar promesas (devolviendo promesas)

Si dentro de un .then() se devuelve otra promesa, el siguiente .then() espera a que esa también resuelva. Así se evita el anidado de los callbacks.

fakeRequestPromise("/page1")
  .then((data) => {
    console.log(data);
    return fakeRequestPromise("/page2"); // se devuelve, no se anida
  })
  .then((data) => {
    console.log(data);
    return fakeRequestPromise("/page3");
  })
  .then((data) => {
    console.log(data);
  })
  .catch((error) => {
    // atrapa el error de CUALQUIERA de las tres peticiones
    console.log("ERROR:", error.message);
  });

6. async / await

async/await es una forma más legible de trabajar con promesas: se ven como código síncrono, pero siguen siendo asíncronas por dentro.

  • Una función marcada async siempre regresa una promesa.
  • await "pausa" la función hasta que la promesa termine, y da directamente el valor resuelto (no hace falta .then()).
  • await solo se puede usar dentro de una función async.
async function tresPeticiones() {
  const data1 = await fakeRequestPromise("/page1");
  console.log(data1);
  const data2 = await fakeRequestPromise("/page2");
  console.log(data2);
  const data3 = await fakeRequestPromise("/page3");
  console.log(data3);
}

tresPeticiones();
Igual que con .then() encadenado, aquí cada await espera a que termine el anterior: las tres peticiones son secuenciales (una después de otra), no simultáneas. Para correrlas al mismo tiempo se necesita Promise.all (sección 8).

7. Manejo de errores: try / catch / finally

Dentro de una función async, un reject (o un throw) se captura con un try/catch normal, como cualquier error síncrono.

async function tresPeticiones() {
  try {
    const data1 = await fakeRequestPromise("/page1");
    console.log(data1);
    const data2 = await fakeRequestPromise("/page2");
    console.log(data2);
  } catch (error) {
    console.log("Algo falló:", error.message);
  } finally {
    // esto se ejecuta SIEMPRE, haya habido error o no
    console.log("Terminó el intento.");
  }
}
finally es ideal para cosas que deben pasar sin importar el resultado: volver a habilitar un botón, ocultar un "cargando...", cerrar una conexión, etc.

8. Promise.all — correr varias promesas en paralelo

Promise.all(arreglo) recibe un arreglo de promesas y regresa UNA promesa que:

  • Resuelve cuando todas las promesas del arreglo resolvieron, con un arreglo de sus resultados (en el mismo orden).
  • Rechaza en cuanto cualquiera de ellas rechaza, con ese mismo error — sin esperar a las demás.

Es la forma correcta de lanzar varias operaciones independientes al mismo tiempo en vez de una tras otra con await secuencial:

// Secuencial: si cada una tarda 500ms, esto tarda ~1000ms
const a = await pedirPerfil(idUsuario);
const b = await pedirPermisos(idUsuario);

// Paralelo con Promise.all: tarda ~500ms (lo que tarde la más lenta)
const [a, b] = await Promise.all([
  pedirPerfil(idUsuario),
  pedirPermisos(idUsuario),
]);
Úsalo cuando las operaciones NO dependen una de la otra (no necesitas el resultado de una para empezar la otra). Si cualquiera falla, el catch de afuera recibe ese error y las demás simplemente se ignoran.

9. Promise.race — la primera que termine, gana

Promise.race(arreglo) también recibe un arreglo de promesas, pero regresa una promesa que se resuelve o rechaza con el resultado de la primera que termine (sea con éxito o con error) — a las demás ya no les importa lo que pase.

const lenta = new Promise((resolve) => setTimeout(() => resolve("lenta"), 3000));
const rapida = new Promise((resolve) => setTimeout(() => resolve("rápida"), 500));

const resultado = await Promise.race([lenta, rapida]);
console.log(resultado); // "rápida" — ganó la que terminó primero

10. Límite de tiempo a algo con race

Promise.race no sirve solo para "ver quién es más rápido": su uso más común es ponerle un límite de tiempo a una operación que podría tardarse demasiado (o quedarse esperando para siempre), compitiéndola contra una promesa que siempre rechaza después de cierto tiempo.

function crearTimeout(ms) {
  return new Promise((_, reject) => {
    setTimeout(() => reject(new Error("Tardó demasiado")), ms);
  });
}

try {
  // Si cobrarCliente() no termina en 5 segundos, gana el timeout y
  // se lanza el error, en vez de quedarse esperando indefinidamente.
  const resultado = await Promise.race([
    cobrarCliente(monto),
    crearTimeout(5000),
  ]);
  console.log(resultado);
} catch (error) {
  console.log("Falló o se agotó el tiempo:", error.message);
}
Si la operación real puede tardar, por ejemplo, hasta 4 segundos y el límite es de 5 segundos, el timeout nunca podrá ganar la carrera — matemáticamente es imposible. Para que el patrón tenga sentido, el límite debe poder ser superado por la operación real al menos algunas veces.
Ojo: Promise.race solo ignora el resultado de la promesa que perdió; no la detiene. Si el cobro tardó 6 segundos y el timeout ganó a los 5, el cobro sigue corriendo y terminará de todos modos. Para evitarlo hay que poder cancelarlo (se puede usar AbortController).

11. Cancelar lo que no ganó la carrera con AbortController

Un AbortController es un objeto con dos partes: una signal (la "señal" que se le pasa a la operación) y un método abort() (el "botón de cancelar"). Quien arranca la operación guarda el controlador; la operación escucha la señal y se detiene cuando se aborta.

function operacionLenta(ms, senal) {
  return new Promise((resolve, reject) => {
    const temporizador = setTimeout(() => resolve("terminó"), ms);

    // Si alguien llama a abort(), se cancela el temporizador y se rechaza.
    senal.addEventListener("abort", () => {
      clearTimeout(temporizador);
      reject(new Error("Operación cancelada"));
    });
  });
}

const controlador = new AbortController();
try {
  await Promise.race([
    operacionLenta(6000, controlador.signal),
    crearTimeout(5000),
  ]);
} finally {
  // Haya ganado quien haya ganado, se cancela lo que siga en curso.
  // Si la operación ya había terminado, abort() no hace nada.
  controlador.abort();
}
clearTimeout(id) cancela un setTimeout pendiente (el id es lo que regresa setTimeout). Es lo que hace que la operación realmente deje de correr, en vez de terminar "en silencio" más tarde. El mismo AbortController se usa también para cancelar un fetch: fetch(url, { signal: controlador.signal }).
